# Chatmu Studio — Automation
**Version:** 1.0
**Requires:** Chatmu Desktop bridge + Ableton Live 12 (AbletonMCP patched Remote Script 1.10.0-chatmu) + Chatmu Ears.
**Used by:** `chatmu-studio-drop-buildup`, `chatmu-studio-arrangement`. **Related:** `chatmu-studio-record`, `chatmu-studio-synth`.

## What does this Skill do?

Turns "que el filtro se abra en el build" into movement that really happens, using the route
Live's API actually supports, and says honestly which part the user has to do.

Answer in the user's language (usually Spanish). Plans as a point table: bar → value in real units.

## What Live's API allows (read this first)

| Where the automation lives | Can the tools write it? |
|---|---|
| **Track automation in the Arrangement** (the lanes under a track) | **No.** Live's API has no access to Arrangement track envelopes. Routes: record it live, or the user draws it from your point table. |
| **Clip envelopes** (inside a clip, Session or Arrangement) | Partly: `local_ableton_lom call` Clip `create_automation_envelope({path: <parameter>})` creates the envelope and `automation_envelope` says if one exists; writing individual points (`insert_step`) is not reachable yet. Clearing (`clear_envelope`, `clear_all_envelopes`) is destructive (approval + clip name). Untested on every Live 12 version: describe first. |
| Device parameter right now | **Yes:** `local_ableton_set_device_param` (real units), `local_ableton_apply`. A static change, not a curve. |
| Movement generated by a device | **Yes:** synced LFOs (Auto Filter, Auto Pan…, read their params) and Chatmu Synth modulations (`local_synth_modulate`). |

Before saying any of this "isn't possible" in the user's Live, run `local_ableton_lom
describe` on the clip / device / parameter: versions differ, and the describe result is
the truth.

## HARD RULES

1. **Say the route and its limits in one line before doing it**, e.g. "La automatización de
   pista en el Arrangement no se puede escribir desde aquí: la grabo en vivo o te dejo los
   puntos para dibujarla".
2. **Real units always:** read `local_ableton_device_params` (names, ranges, `display_value`)
   and express every point as Live shows it ("Frequency 200 Hz → 8 kHz").
3. **Recording is destructive:** `local_ableton_record` asks approval every time, always ends
   with `action: "stop"`, and you say what will be recorded and where.
4. **Undo:** every write is one undo step (`local_ableton_undo`); log what you changed.

## Phase 0 — Plan

1. `local_ableton_snapshot` → the track, its devices, the section in bars (locators).
2. Which parameter: filter cutoff (Auto Filter `Frequency`), volume (Utility `Gain` — keep
   the fader for the mix), send (track send), pitch (clip `pitchCoarse` for audio, a synth
   pitch parameter/modulation for MIDI), dry/wet of a reverb/delay.
3. Point table (4/4, bar N = beat (N−1)×4):

| Compás | Valor |
|---|---|
| 57 | Frequency 200 Hz |
| 64.4 | Frequency 8 kHz |
| 65 (drop) | Frequency 20 kHz (abierto) |

Prefer a device you add for the move (Auto Filter / Utility on the track) over a mix device
the user already set.

## Phase 1 — Pick the route

| Need | Best route |
|---|---|
| A sweep/rise in one section of the Arrangement | **A. Record it live** or **D. Point table** |
| Movement that repeats with a clip (every loop) | **B. Clip envelope** (if the describe shows it can be filled) or C |
| Rhythmic/cyclic movement (wobble, tremolo, slow filter drift) | **C. LFO in a device / Chatmu Synth** |
| A section-wide static change (more reverb in the chorus) | D (two points per section edge), or a separate return/track for that section |

**A. Record it live (Arrangement):** set the loop/playhead a bar before the section,
`local_ableton_record { action: "start", mode: "arrangement" }` (approval), then the USER
moves the knob (smoothest), or you step the parameter with
`local_ableton_set_device_param` once per beat or bar (gives a stepped curve — say so).
Then `{ action: "stop" }`. Whether remote changes are written as automation depends on
Live's automation arm: check `local_ableton_lom describe live_set` for the automation-record
property before relying on it.

**B. Clip envelope:** `local_ableton_lom describe` the clip; if `create_automation_envelope`
is allowed, create it for the parameter's path and tell the user it holds one value until
points can be written; finish the curve with D. Don't claim a curve you couldn't write.

**C. LFO:** Auto Filter / Auto Pan with sync on (rate from the read: 1/4, 1 bar, 4 bars…);
in Chatmu Synth `local_synth_list_params { filter: "lfo_1" }` → `local_synth_modulate
{ source: "lfo_1", destination: <exact param>, amount }`.

**D. Point table for the user:** the table above + the exact lane: "En el Arrangement,
pista **Synth Lead**, carril **Auto Filter → Frequency**, dibuja: …". Short and exact.

## Ears verification

Play the section (`local_ableton_transport { action: "play", fromBeat }`), `local_ears_listen`
for its length (one call), then `local_ears_render { captureId, view: "spectrogram" }` for a
filter sweep (the top of the spectrum should rise over time) or `"loudness"` for a volume
rise. Report "brillo de 1.2 kHz a 9 kHz en 8 compases". If you couldn't listen or can't see
the render, say **"no verificado"**.

## Don'ts

- Don't say you wrote Arrangement automation: the tools can't.
- Don't leave recording armed or the transport running.
- Don't move the mix fader to automate; use a Utility.
